# Сетевая демо-аркада

Одна комната на четырёх участников, включая ведущую: Документы → один вопрос → Серёга-босс. У каждого свой герой, прогресс задания, ответ и здоровье; карта и босс общие. Играть нужно на компьютере с клавиатурой. При входе доступны 12 цветов героя.

## Репетиция

Адрес для участников: [открыть демо](https://chepuha-arcade-demo.madlib.workers.dev/arcade). Для ведущей: [открыть пульт](https://chepuha-arcade-demo.madlib.workers.dev/arcade?host=1). Готовность конкретного выпуска и результат сетевой проверки фиксируются в `docs/ARCADE_RELEASE.json`; наличие адреса само по себе не подтверждает успешную проверку. Поля `fourPlayerCheckEnvironment` и `hostLoginCheckEnvironment` отличают изолированный локальный прогон от проверки опубликованной комнаты.

1. Ведущая открывает `/arcade?host=1`, выбирает ник и входит с отдельным паролем ведущей аркады.
2. Задаёт отдельный пароль участников (минимум шесть символов) и открывает комнату.
3. Трое участников открывают `/arcade`, вводят свои ники и пароль комнаты. Присоединяться можно в лобби до начала уровня.
4. Когда все появились в списке, ведущая нажимает «Начать уровень».
5. Каждый игрок по платформам добирается до «Заголовок», нажимает E, затем до «Сохранить» и снова нажимает E. После обеих личных задач нужно спуститься к выходу справа и нажать E. Герой исчезает с карты, у ника появляется галочка. Раньше выполнения задания выйти нельзя. Кнопки также доступны мышью, когда герой рядом.
6. Когда все подключённые игроки вышли, ведущая переводит команду к вопросу. Все герои возвращаются на карту. Каждый выбирает ответ, стоя на площадке. Ведущая раскрывает правильный ответ и начинает бой.
7. Все стреляют в босса, удерживая F, и перепрыгивают его снаряды. После смерти герой лежит с глазами-крестиками; бой продолжается, пока жив хотя бы один подключённый игрок.
8. После репетиции ведущая нажимает «Закрыть комнату». Игроки отключаются, закрытие сохраняется на сервере.

Пароль участников можно изменить в лобби: существующие гостевые входы аннулируются, участники входят заново. Новые участники не допускаются без подключённой ведущей. При потере связи ведущей игра встаёт на паузу; после возвращения она нажимает «Продолжить».

Перезагрузка страницы восстанавливает вход и героя. Отключённое место сохраняется 45 секунд. Комната не завершается из-за перехода в другую вкладку: остановится только герой этого игрока.

Управление: A/D или ←/→ — идти; Space/W/↑ — прыгать; E — действие; F — стрелять; Esc — пауза для ведущей. Клик по полю возвращает фокус управления.

Базовое здоровье босса — 48 HP на участника. Если правильных ответов больше, здоровье уменьшается; если ошибок больше — растёт. Поправка равна `30% × (ошибки − правильные) / число участников`: все верно дают −30%, все неверно +30%, поровну — без изменений. Отсутствие ответа считается ошибкой. Каждая новая попытка дополнительно уменьшает здоровье на 25%, до минимума 10 HP на участника. У игроков по 3 HP. Пульт позволяет ставить паузу, пропускать этап, повторять бой и начинать сценарий заново.

## Инфраструктура и выпуск

Публичная точка входа — Worker Cloudflare `chepuha-arcade-demo` по адресу `https://chepuha-arcade-demo.madlib.workers.dev`. Он обслуживает WebSocket-комнату `/parties/arcade/demo` через SQLite Durable Object `ArcadeDurable` и проксирует интерфейс Next.js с отдельного Vercel origin `https://chepuha-arcade-demo.vercel.app`. Страница, API входа и WebSocket для игроков доступны на одном Worker origin.

HTTP-прокси разрешает только `/arcade`, `/arcade/local`, `/api/arcade/*`, `/_next/*` и `/favicon.ico`. Он не открывает остальные страницы и API каталога; корень Worker перенаправляет на `chepuha.fun`. `ARCADE_FRONTEND` задаёт разрешённый HTTPS origin Vercel. Адаптер комнаты использует общий сервер аркады и рассчитывает игру; снимки состояния отправляются 20 раз в секунду. Настройки комнаты и состояние сохраняются в storage.

Vercel deployment создаётся в существующем проекте `madlib` с флагами `--prod --skip-domain`, затем получает отдельный production alias `chepuha-arcade-demo.vercel.app`. Основной `chepuha.fun` не переключается, комнаты «Чепухи» продолжают использовать прежний Neon API. Технические URL Vercel защищены Vercel Protection; защиту не отключали. Публичный Worker entrypoint нужен также потому, что прямые hostname Vercel недоступны из текущей сети.

Хостинг PartyKit отказал в публикации с ошибкой Cloudflare «10000 Workers custom domains on zone partykit.dev», в том числе для существующего проекта и последнего CLI 0.0.115. Размещение в собственном аккаунте Cloudflare обходит этот общий домен; PartyKit остаётся вариантом для локального запуска.

Vercel и Cloudflare используют общий серверный `ARCADE_SECRET`; Vercel также требует `NEXT_PUBLIC_ARCADE_HOST` с hostname этого Worker. Пароль ведущей задаётся отдельной чувствительной переменной `ARCADE_HOST_PASSWORD` на Vercel. Только если она не задана, вход использует `ADMIN_PASSWORD` как совместимый резервный вариант. При заданном пароле аркады вход проверяет только этот пароль, а админская сессия «Чепухи» не даёт доступ к пульту.

Форма ведущей отправляет JSON с полем `password` на `/api/arcade/host-login`. Успешный вход устанавливает подписанную HttpOnly cookie `arcade_host_access` на 12 часов с областью `/api/arcade`. Затем API выдаёт билет комнаты. Серверные значения секретов и паролей не включаются в клиентский код и не сохраняются в репозитории. Билеты комнаты действуют 12 часов; гостевые билеты отзываются при закрытии или смене пароля участников. Вход и пароль участников не зависят от пароля ведущей.

Выпуск запускается командой `node scripts/release-arcade.mjs`. Порядок действий скрипта:

1. Проверяет, что предыдущая репетиция закрыта и ведущая отключена, и генерирует новый серверный секрет.
2. Публикует Worker, передаёт ему секрет и проверяет защищённый вход сервера комнаты.
3. Передаёт Vercel секрет и hostname комнаты; если процессу передан `ARCADE_HOST_PASSWORD`, сохраняет его как Sensitive через stdin. Создаёт отдельный production deployment с `--skip-domain` и ждёт `READY`.
4. Назначает deployment отдельный alias `chepuha-arcade-demo.vercel.app`.
5. Повторно публикует Worker с `ARCADE_FRONTEND`, включая HTTP-прокси к этому alias; повторно устанавливает тот же секрет и проверяет доступность страницы через Worker.
6. Запускает реальный сетевой сценарий с четырьмя WebSocket-клиентами. Только после успешной проверки пишет `status: READY` и `fourPlayerCheck: passed` в `docs/ARCADE_RELEASE.json`; тестовая комната остаётся закрытой.

Отдельный `vercel.arcade.json` выбирает Webpack для этого выпуска: установленный Turbopack ошибается при обработке Google Fonts. Начальный секрет передаётся Wrangler через временный файл с правами 0600, который сразу удаляется; после каждой загрузки он также применяется через `wrangler secret put` со stdin. Vercel получает его через stdin. При ошибке публикации или проверки выпуск не считается готовым: нужно исправить причину и повторить команду. Для старого хостинга существует явный `--partykit`, сейчас его публикация блокируется сервисом.

Полный сетевой прогон проверяет обычный вход ведущей через `/api/arcade/host-login`, если процессу передан актуальный `ARCADE_HOST_PASSWORD` либо резервный `ADMIN_PASSWORD`. Проверка использует тот пароль, который настроен для выпуска. Если пароль не передан процессу, тестовая ведущая получает подписанный билет через защищённый серверный протокол, а проверка правильного пароля остаётся отдельным шагом. `hostLoginCheck` в файле выпуска отражает эту разницу. Команда `node scripts/check-arcade-host.mjs` с актуальным паролем в окружении проверяет обычный вход, cookies, восстановление сессии и WebSocket; комнату она не открывает. Секретные production-переменные Vercel не выгружаются, а локальная настройка может отличаться от production.

## Локальная разработка и проверка

Без `NEXT_PUBLIC_ARCADE_HOST` development-маршрут `/arcade` показывает прежний одиночный прототип. Его также можно открыть по `/arcade/local` в development. Эти локальные маршруты не заменяют сетевую репетицию.

```bash
npm run dev:next -- --hostname 127.0.0.1 --port 3010
./node_modules/.bin/tsx scripts/check-arcade-engine.ts
./node_modules/.bin/tsx scripts/check-arcade-room.ts
./node_modules/.bin/tsx scripts/check-arcade-server.ts
node scripts/check-arcade-e2e.mjs
node scripts/check-arcade-e2e.mjs --cloudflare
npm run lint
./node_modules/.bin/tsc --noEmit
ARCADE_TEST_BUILD_DIR=.next-arcade-test npm run build -- --webpack
```

E2E самостоятельно запускает изолированные Next.js/PartyKit с временными секретами и разными сгенерированными паролями аркады и админки «Чепухи», проверяет вход ведущей с паролем аркады и четыре WebSocket-клиента, затем закрывает комнату и останавливает процессы. Остальные уровни и финальный квиз пока не входят в демо.
